# Notification digests

Notifications are optional and disabled by default. Read only updater-returned `alerts` from `state/last-run.json` or a private archived `*.result.json`; never build a delivery from finder packets, raw discovery inputs, candidate profiles, email bodies, or workbook rows.

Run `npm run notify [-- --input <private-result.json>]` first. Preview writes nothing and returns the version-1 digest, destination requests, classifications, quiet-hour deferrals, and exact `NAPP-…` approval ID. Do not add `--apply` unless the user explicitly approves that exact ID. Apply creates only idempotent private files under the configured state directory and never changes the workbook.

The digest is bounded and privacy-minimized. It may contain alert-backed job metadata and, only when configured for that destination, the selected resume label. It must not contain candidate identity, profile evidence, resume files or paths, raw run payloads, Gmail content, recipient addresses, connector endpoints, credentials, or private filesystem paths.

`private_file` destinations create a local request. `connector` destinations create an outbox request with an opaque connection reference and deterministic `not_before`. The digest writer never invokes a connector or performs an external send.

Live connector execution is a separate boundary. Keep the private version-1 profile at `state/notification-connectors/<profile_id>.profile.json`; it may contain only the HTTPS endpoint, a bearer-token environment-variable name, exact destination allowlist, bounded request policy, and required idempotency declaration. The credential value remains solely in the process environment. Preview the profile with `npm run connector-profile -- --profile <private-profile>`; preview writes nothing and exports only a sanitized deterministic binding plus exact `NCON-…` approval. Only exact approved `--apply` may import that binding under private state, and the binding contains neither the endpoint nor the credential environment-variable name.

Preview a queued connector request with `npm run notify-send -- --request <private-outbox-request> --profile <private-profile>`. Preview never reads the credential or uses the network. A live attempt requires the user to separately approve that request's exact `NAPP-…` ID, then add `--send --approve NAPP-EXACT-ID`. The dispatcher must revalidate the adapter-neutral request, matching sanitized binding, local notification destination, private-profile destination allowlist, profile enabled flag, `not_before`, HTTPS-only endpoint, byte limits, timeout, deterministic retry schedule, and stable request-ID idempotency key before reading the credential.

Receipts and recovery markers are sanitized: they contain hashes, opaque IDs, bounded HTTP status, and safety flags, but no endpoint, credential, response body, request items, or candidate artifacts. A confirmed-delivery marker recovers its receipt without resending. An unconfirmed retry uses the same idempotency key; never claim exactly-once delivery unless the external endpoint actually honors that header. Never reinterpret a notification destination as permission to submit an application, update a job, send general email, or contact a recruiter.

If request apply or connector dispatch fails, preserve the redacted `pending-notification-*.json` marker. Use `npm run pending` and only its exact recovery command. Repeating an applied digest is idempotent; repeating a confirmed connector request returns its sanitized receipt without network activity.

Use `npm run notify-health` for read-only connector delivery health. It inspects only bounded private connector outbox requests, sanitized receipts, sanitized provider-status observations, and redacted connector/status recovery markers. It reports deterministic confirmed, rejected, unknown, deferred, queued, and stale status plus hashed invalid/orphaned artifact references. It never reads connector profiles, endpoints, credential sources or values, request items into its report, response bodies, or candidate artifacts; it never writes state, invokes a connector, or retries a request. For any recovery-required state, run `npm run pending` and review its exact command. Real health reports remain private and must not be staged.

Provider-side status reconciliation is separate from delivery and local health inspection. Keep a private version-1 status profile under `state/notification-status-connectors/` and preview/import only its sanitized binding with `npm run status-profile`; exact apply requires its `NSTATCON-…` approval and exports neither endpoint nor credential environment-variable name. Preview an outbox request with `npm run notify-status -- --request <private-request> --profile <private-status-profile>`. Preview performs no credential lookup or network access. One live read-only query requires `--probe --approve NSTAT-EXACT-ID`, an enabled status profile, exact request/profile/binding match, exact destination allowlist, HTTPS, one bounded attempt, redirect rejection, and an environment-supplied bearer value. The strict response contains only the matching request ID, delivery status, and observation timestamp. Persist only the sanitized observation; failures retain a redacted marker recoverable through `npm run pending`. Never use a status probe to send, retry, or mutate a notification.

The version-2 health report additionally reconciles sanitized provider observations and status-probe recovery markers. Provider `delivered`, `rejected`, `unknown`, and `pending` evidence maps deterministically into the existing health states. The inspector remains profile-, credential-, endpoint-, network-, retry-, and write-free.
