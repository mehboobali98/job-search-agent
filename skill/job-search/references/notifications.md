# Notification digests

Notifications are optional and disabled by default. Read only updater-returned `alerts` from `state/last-run.json` or a private archived `*.result.json`; never build a delivery from finder packets, raw discovery inputs, candidate profiles, email bodies, or workbook rows.

Run `npm run notify [-- --input <private-result.json>]` first. Preview writes nothing and returns the version-1 digest, destination requests, classifications, quiet-hour deferrals, and exact `NAPP-…` approval ID. Do not add `--apply` unless the user explicitly approves that exact ID. Apply creates only idempotent private files under the configured state directory and never changes the workbook.

The digest is bounded and privacy-minimized. It may contain alert-backed job metadata and, only when configured for that destination, the selected resume label. It must not contain candidate identity, profile evidence, resume files or paths, raw run payloads, Gmail content, recipient addresses, connector endpoints, credentials, or private filesystem paths.

`private_file` destinations create a local request. `connector` destinations create an outbox request with an opaque connection reference and deterministic `not_before`. The digest writer never invokes a connector or performs an external send.

Connector capability discovery is a separate network-free import boundary. A real account or adapter may produce a strict version-1 private export outside repository code, without credentials or endpoints, under `state/notification-connector-discovery/exports/<NCAPEXP-…>.capabilities.json`. Preview it with `npm run connector-discover -- --input <private-export>`. The importer validates bounded operations, renderers, target count and size, exact filename, containment, and symbolic links; it performs no authentication, credential access, connector call, status probe, profile mutation, or delivery.

Only `--apply --approve NCAP-EXACT-ID` may atomically store the previewed sanitized catalog under `state/notifications/discovery/`. The catalog removes the account reference, target labels, and native targets; retains only the opaque connection reference, deterministic target IDs/hashes, channels, operations, renderers, counts, and safety flags; and never authorizes a send. Repeating an unchanged import is idempotent. A failed commit leaves a redacted `pending-notification-discovery-*.json` marker whose exact private recovery is reported by `npm run pending`.

Use `npm run connector-drift -- --catalog <private-catalog> --binding <private-binding>` only as a read-only compatibility check over those two sanitized artifacts. It reads neither the raw capability export nor connector profile, performs no credential/environment/endpoint/network/write/retry/delivery operation, and never grants send authorization. An exact hash-bound version-2 native target may align; connection, channel, renderer, or target drift is incompatible. A version-1 or adapter-neutral destination is `review_required` because its native target is intentionally not hash-bound. Never infer that missing identity. The private report omits target hashes as well as native targets, labels, account identifiers, endpoints, credentials, paths, and candidate data.

Live connector execution is a separate boundary. Keep the private version-1 or version-2 profile at `state/notification-connectors/<profile_id>.profile.json`; it may contain only the HTTPS endpoint, a bearer-token environment-variable name, exact destination allowlist, bounded request policy, required idempotency declaration, and for version 2 an exact renderer/native-target policy. Version 1 sends the adapter-neutral request unchanged. Version 2 supports `adapter_neutral_json_v1` and bounded `slack_blocks_v1`; the Slack target stays only in the private profile. The credential value remains solely in the process environment. Preview the profile with `npm run connector-profile -- --profile <private-profile>`; preview writes nothing and exports only a sanitized deterministic binding plus exact `NCON-…` approval. Only exact approved `--apply` may import that binding under private state, and the binding contains neither the endpoint, credential environment-variable name, nor native target.

Preview a queued connector request with `npm run notify-send -- --request <private-outbox-request> --profile <private-profile>`. Preview never reads the credential or uses the network and returns neither rendered content nor a native target. A live attempt requires the user to separately approve that request's exact `NAPP-…` ID, then add `--send --approve NAPP-EXACT-ID`. The dispatcher must revalidate the adapter-neutral request, matching sanitized binding, local notification destination, private-profile destination/renderer/target allowlist, profile enabled flag, `not_before`, rendered byte limit, HTTPS-only endpoint, timeout, deterministic retry schedule, and stable request-ID idempotency key before reading the credential.

Receipts and recovery markers are sanitized: they contain hashes, opaque IDs, bounded HTTP status, and safety flags, but no endpoint, credential, native target, rendered payload, response body, request items, or candidate artifacts. A confirmed-delivery marker recovers its receipt without resending. An unconfirmed retry uses the same deterministic body and idempotency key; never claim exactly-once delivery unless the external endpoint actually honors that header. Never reinterpret a notification destination as permission to submit an application, update a job, send general email, or contact a recruiter.

If request apply or connector dispatch fails, preserve the redacted `pending-notification-*.json` marker. Use `npm run pending` and only its exact recovery command. Repeating an applied digest is idempotent; repeating a confirmed connector request returns its sanitized receipt without network activity.

Use `npm run notify-health` for read-only connector delivery health. It inspects only bounded private connector outbox requests, sanitized receipts, sanitized provider-status observations, and redacted connector/status recovery markers. It reports deterministic confirmed, rejected, unknown, deferred, queued, and stale status plus hashed invalid/orphaned artifact references. It never reads connector profiles, endpoints, credential sources or values, request items into its report, response bodies, or candidate artifacts; it never writes state, invokes a connector, or retries a request. For any recovery-required state, run `npm run pending` and review its exact command. Real health reports remain private and must not be staged.

Provider-side status reconciliation is separate from delivery and local health inspection. Keep a private version-1 status profile under `state/notification-status-connectors/` and preview/import only its sanitized binding with `npm run status-profile`; exact apply requires its `NSTATCON-…` approval and exports neither endpoint nor credential environment-variable name. Preview an outbox request with `npm run notify-status -- --request <private-request> --profile <private-status-profile>`. Preview performs no credential lookup or network access. One live read-only query requires `--probe --approve NSTAT-EXACT-ID`, an enabled status profile, exact request/profile/binding match, exact destination allowlist, HTTPS, one bounded attempt, redirect rejection, and an environment-supplied bearer value. The strict response contains only the matching request ID, delivery status, and observation timestamp. Persist only the sanitized observation; failures retain a redacted marker recoverable through `npm run pending`. Never use a status probe to send, retry, or mutate a notification.

The version-2 health report additionally reconciles sanitized provider observations and status-probe recovery markers. Provider `delivered`, `rejected`, `unknown`, and `pending` evidence maps deterministically into the existing health states. The inspector remains profile-, credential-, endpoint-, network-, retry-, and write-free.
